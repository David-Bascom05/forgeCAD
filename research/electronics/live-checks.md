# Solving DRC every frame

**Make the default request a complete, current answer after each edit.** If incrementality keeps every enabled rule current at the display rate, publish the full board verdict every frame. Collect a time and coverage record for each rule family so the team can identify exactly what still prevents that. A cheap rule can certify a whole board on a local edit by establishing that every finding outside the affected set remains valid. Evaluating only the visible viewport cannot establish that.

A drag produces an immutable base revision and a transient placement overlay. Move C3, transform its land anchors and outlines once, fetch incident soft relationships, and query the swept old/new boxes on each affected layer. Resolve side, courtyard overlap and pin distance against the same proposed pose. Next repair contacts, short/open findings and any affected routes, zones, checks and system interfaces. The move of an internal capacitor leaves unrelated harness endpoints current if their input values are equal. A move of the board's mating connector reaches its installed occurrences and harness. If the designer then presses Escape, discard the overlay. On acceptance, commit the same checked delta atomically and retain the computed answers whose exact inputs agree.

**Publish a finding a designer can act on.** Each result carries a snapshot or overlay revision, provider, rule and policy revision, affected objects, units, side/layer or sheet, measured value and threshold, and the geometric or graph witness. Give it a stable identity so the same warning updates as the cursor moves. Highlight the pair, show what changed, and let a click take the designer to the owning rule, pin or parameter. Suggestions to edit a derived value should take the designer to its drivers. A previous revision may be displayed as previous. A green “all checks passed” requires current coverage for every required provider.

## Measurements on the existing implementation and real boards

**Existing .fg baseline.** I timed the public in-process `forge_lang::run` entry point on the repo's `sheet/hat.fg`, 200 samples per case on this Linux Xeon Platinum 8573C host, 4 CPU quota, existing Cargo debug-tree library, Rust 1.99.1. Build enabled, optional detailed checks disabled. Timings enclose the call, including parse, checking, evaluation and any rebuild. File I/O, UI paint and process startup are outside the measurement. Cold here means a fresh language cache within the process. The error case starts from valid input each time. [Fixture](https://github.com/David-Bascom05/forgeCAD/blob/d9d93a0aa2e2cc3a915a9f8fcd96e2d192be9542/interface/forge-lang/parts/sheet/hat.fg) · [Reproduction bundle](probes/README.md)

| Edit | p50 | p95 | p99 | Kernel history stages reused / rebuilt |
|---|---:|---:|---:|---:|
| Fresh session cache | 4.65 ms | 5.60 ms | 6.32 ms | 0 / 3 |
| Same source | 0.85 ms | 1.25 ms | 1.52 ms | 3 / 0 |
| Successive unique width edits | 8.18 ms | 10.72 ms | 16.26 ms | 1 / 2 |
| Restore the previous width after changing it | 1.04 ms | 1.38 ms | 1.48 ms | 3 / 0 |
| Replace a length with an angle | 0.46 ms | 0.76 ms | 0.95 ms | 1 / 0 |

The error is `WrongDim`. The result points at the width argument and identifies the required Length and received Angle. The width series was slower at p95 than cold-building this small fixture. Track discarded work, cache size and edit sequence alongside hit counts. A high hit rate alone tells us little about response time.

**A runnable per-frame DRC experiment.** I took the front-copper vias with assigned nets from two published boards. The Rust probe checks a deliberately narrow rule: two different-net circular via lands must have at least 0.20 mm outer copper clearance, with equality passing. It compares squared integer distances at nanometre precision. The full pass checks every pair. For each synthetic frame the incremental pass starts with the base board's complete violation set, removes entries involving the moved via, and evaluates that via against all others. The two passes returned identical **sets of offending pairs on all 4,000 overlays**. Each overlay starts from the unchanged original board. The moves include ±X translations and deliberate near-neighbour placements. Rules, via diameters and net assignments stay fixed. [Koyomi board](https://github.com/TensorFleet/koyomi-lvds-hat/blob/bd6af086f8528749ccd98f745891a731011d5fac/koyomi-lvds-hat.kicad_pcb) · [Inkplate board](https://github.com/SolderedElectronics/Soldered-Inkplate-2-hardware-design/blob/57c5179a669f5237cbca6a0c0cbc7aa936c7b1df/CAD/V1.2.3/Inkplate%202.kicad_pcb) · [Source, inputs and commands](probes/README.md)

| Board | Vias | Overlays changing the violation set | Complete rescan p95 / p99 | Incremental whole-board verdict p95 / p99 |
|---|---:|---:|---:|---:|
| Koyomi LVDS HAT | 112 | 668 / 2,000 | 42.88 / 172.16 µs | 0.63 / 0.95 µs |
| Inkplate 2 | 393 | 289 / 2,000 | 261.13 / 673.55 µs | 1.64 / 1.94 µs |

These are native single-process compute times, with `rustc -O`, on the host above. The subset excludes tracks, arbitrary pads, pours, drill clearance, rule selection, source publication and rendering. The result is encouraging in two ways. Even a simple full rescan fits a frame on these fixtures for this rule. Comparing a moved via with 392 others also leaves substantial time for other rules. The 82.14 ms Boolean on 112 via centres in the [planar geometry study](backend.md#4-planar-copper-geometry-and-the-forgecad-reuse-decision) shows the opposite end of the performance range. Both measurements matter when choosing what to build next.

**How local are these boards?** For a +0.25 mm X move of each front via, I also queried the union of old and new boxes expanded by a fixed 0.20 mm and compared a 2 mm spatial grid with an exhaustive scan. Including front-layer tracks, vias and pads, Koyomi had 669 objects and a median of 2 candidate neighbours, p95 of 6, maximum 8. Inkplate had 940 objects and median 0, p95 of 4, maximum 8. The grid and scan agreed on all 505 query sets. These are bounding-box candidates and exclude zones. Dense BGAs, long diagonal tracks and board-wide pours need separate fixtures.

## Which work an edit must revisit

| Edit | Index, invalidation and completion condition |
|---|---|
| Type into a parameter or rename a pin | Use the existing number fast path where applicable. Incrementally rebind the enclosing scope and its actual readers; unresolved names also depend on the scope's name index. For a rename, return affected paths and update text spans. Stop downstream when the exported value and structural identity are equal. An unfinished expression yields a local diagnostic immediately |
| Move a schematic label, wire or junction | Use per-sheet segment/text indexes and pin attachments. A visual-only move affects readability witnesses. A junction edit may split a net. Traverse the previous affected connected component on deletion; union-find alone only handles merges. If a global label or sheet port changes, visit every affected instance and then shared consumers |
| Move a footprint or shove a route | Read the changed objects, old and new layer intervals, spatial cells and the applicable maximum interaction distances. Check both previously reported findings and new candidates. A previously empty cell is an input. Use exact primitive predicates near rule thresholds and index relation readers by endpoint. Propagate until the affected contact components and rule decisions stabilize |
| Alter a rule, swap a footprint, or change a stack | Index by rule application, selector properties and candidate populations. Invalidate newly matching objects as well as old matches. For an increased clearance, old search bounds can miss a new violation. Re-evaluate rule precedence, expand the search envelope, and revisit geometry, paths and sign-off that read the changed fields |
| Change a zone, island or thermal | Track affected polygons, neighbours by priority, connectivity and attachment to anchors. A narrow neck cut can disqualify a remote island. Reconcile connectivity across tile borders; when an effect can travel, follow it to closure or refill the entire zone. Publish the exact filled-copper verdict after stitching and island classification |
| Move a board in an assembly or edit a harness interface | Reuse board-local copper and the electrical pin map if unchanged. Update occurrence transforms, assembly spatial pairs and affected mating/cavity endpoints; a repeated board has independent placements. For a harness path length or interference finding give its installed occurrence and solver coverage |
| Change an analysis model or generate a release | Cache extracted nets, geometry and material inputs, topology-dependent sparse structure and operating conditions where applicable. Timing, impedance or simulation outputs carry solver model and uncertainty. Reuse a factorization only under its mathematical preconditions. A release consumes one immutable, fully checked snapshot with a manifest of its dependencies |

Keep frequently queried geometry in contiguous, layer-local storage, with generation-checked handles and reverse readers. Intern stable IDs and pin pairs once. Size the spatial index from actual neighbour distributions and bound the cost of long shapes. Separate stable board data from transient edits to avoid copying a board for a pointer event. Keep critical-path jobs small, coalesce superseded pointer positions, cancel at bounded intervals, and preserve complete transactions. Publish immutable results in deterministic order regardless of worker schedule. Put a limit on cached overlays and retained geometry and measure memory during a long drag. Switching a layer, net class, library model or variant must never produce a wrong cache hit.

## Performance gates that can change the product

Use both real boards above. Add a reproducible medium fixture with 10,000 copper primitives, 1,000 placed footprints, eight copper layers, and 20 schematic sheets. Add a separate dense fixture with 100,000 primitives, 16 layers, repeated hierarchy, at least one large shared plane, and two installed board occurrences. Record layer occupancy, pad/vertex counts, zone intersections, enabled rule mix, fonts, cache state and CPU/GPU. These proposed numbers need an actual named reference desktop, browser/native measurements and a versioned corpus before becoming claims.

| Proposed acceptance gate | Medium fixture target | What the stopwatch includes |
|---|---|---|
| Typed edit and local explanation | p95 ≤2 ms / p99 ≤4 ms backend | Edit received through semantic result, including spans, drivers and actionable message |
| Live sheet legibility, placement relationships, exact local clearance and courtyard checks | p95 ≤4 ms / p99 ≤8 ms combined backend | Gesture delta through complete current answers of these enabled families. Run them together. Show feedback on the next 60 Hz frame under the reference presentation pipeline |
| 120 Hz routing/placement stretch goal | p95 ≤2 ms / p99 ≤4 ms combined backend | Leave time in the 8.33 ms frame for input, scene update, paint and compositor. Separately measure input-to-visible p95/p99, missed frames and age of the displayed overlay under continuous input |
| Full live DRC on ordinary local edits | p95 ≤8 ms / p99 ≤12 ms backend at 60 Hz; seek ≤4 ms for 120 Hz | Include all enabled providers, finding removal/publication and proof that unaffected regions remain current. Count **fraction of all frames with full current coverage**. Report global pour/split edits separately; every late result is a missed target |
| Local logical or copper topology split, routing shove and installed connector update | p95 ≤16 ms / p99 ≤32 ms for the scripted edits | Exact changed partition, legal route or explicit blocked result, current system endpoints and cross-probes. A stale frame increments coverage lag even when the cursor stays smooth |
| Medium cold open and global solve | first usable drawing p95 ≤250 ms, complete cold net compilation ≤500 ms, cold full fill plus DRC ≤2 s p95 | Fresh process, locked library closure, representative rule/zone configuration; count any reused on-disk cache separately. Initial targets for the large fixture are ≤1 s, ≤2 s and ≤10 s respectively. Track full sign-off and export separately by output mix |

Record wall time and result age, cached and recomputed queries, p50/p95/p99 and maximum stalls, bytes allocated, candidate fan-out and reason each late check missed. Use at least 10,000 consecutive input samples in warmed frame-gate runs, plus cold opens and throttled CPU tests. Exercise worst cases deliberately: move a connector between two crowded areas, remove a bridge in a plane, increase a board-wide rule, and change a commonly instantiated symbol. Compare incremental results with a fresh solve at checkpoints, on every frame for small fixtures, and after replay under different worker counts. A fast cursor over stale DRC does not meet the every-frame gate.

Speed creates features of its own. During a drag, display the nearest **legal** placement respecting locks and the exact witnesses for alternatives. Scrub a clearance parameter and show which pairs cross the threshold first. On a capacitor move, show both the placement budget and collateral route violations while the user can still change direction. During schematic cleanup, preview whether a label move merely improves readability or actually merges nets. Each can use the same transient revision and verified result the eventual edit would commit.

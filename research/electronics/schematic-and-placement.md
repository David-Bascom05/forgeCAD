# Schematic authoring and placement intent

A designer should be able to draw a schematic, place its components, discover that a bypass capacitor is too far from a supply pin, and fix it without opening a source editor. The GUI must be a first-class author of native `.fg`. A parsed file and a file drawn entirely with the mouse must give the same schematic, electrical connections, placement intent, explanations and available edits. This chapter proposes the contract. The electronics operations and example messages below have yet to be implemented.

## What to carry forward from ForgeCAD

In today's language, a number has a dimension and provenance. A parameter can drive a dimension directly, or its value can depend on several earlier parameters. The latter gives a tool a list of inputs it can expose. Structural observations such as a branch decision matter too. The language reports typed errors, source spans and, for certain errors, executable edit operations. A typed source edit aims to preserve surrounding bytes. The existing harness already lets a designer refer to an actual connector pin as `J1[1]` or `J2.a`, and its geometric references follow solved assembly placements. These are the precedents for picking an MCU pin or a capacitor land on screen. [Dimensions and drivers](https://github.com/David-Bascom05/forgeCAD/blob/d9d93a0aa2e2cc3a915a9f8fcd96e2d192be9542/interface/forge-lang/src/values.rs#L10) · [Typed errors and fixes](https://github.com/David-Bascom05/forgeCAD/blob/d9d93a0aa2e2cc3a915a9f8fcd96e2d192be9542/interface/forge-lang/src/error.rs#L1079) · [Source edits](https://github.com/David-Bascom05/forgeCAD/blob/d9d93a0aa2e2cc3a915a9f8fcd96e2d192be9542/interface/forge-lang/src/edit.rs#L512) · [Harness reference](https://github.com/David-Bascom05/forgeCAD/blob/d9d93a0aa2e2cc3a915a9f8fcd96e2d192be9542/interface/forge-lang/src/reference.md#L1373)

The actual execution path is specific. A successful previous parse can be patched for certain single-number edits. Other edits go through the parser. Static checks run, then evaluation, during which additional type errors can arise. The builder reuses unchanged history prefixes, and can recover matching earlier stages on undo. It also retains some independent computations and assembly/sketch state. The native editor coalesces queued edits and can publish changed faces or assembly shape ahead of detailed checks. Prior check rows can remain visible with a stale marker. A PCB contains many independently editable objects. The equivalent of moving one footprint is updating its readers, even when its source statement happens to be near the top of a file. ## What a hand-drawn schematic records

| A designer does this on the canvas | The edit records in native source | What becomes available immediately |
|---|---|---|
| Places a symbol, selects a package or exchanges a gate | Library definition and revision, qualified occurrence, symbol unit, anchor, rotation/mirror, and pin–pad mapping where known | Typed pins and pin roles from the library, occupied symbol area, and a precise finding if a package mapping is missing |
| Draws a wire, junction, bus entry, label or sheet port | Electrical attachments and scope plus sheet coordinates, bends, junction intent and label anchor | Connectivity and ERC, legibility checks, cross-probing to a pin or board land |
| Draws a labeled functional block, creates a repeated channel, or groups a selection | Explicit membership and instance scope. A graphical annotation can be promoted to a functional group in the inspector | A suggested placement group with individually editable member relationships. Identical channel instances keep separate members |
| Drags a component or label | A small typed edit to the placement or label anchor, with electrical endpoints retained for a presentation-only move | Updated intersections, clipped text, air gaps between label and wire, and any affected wires or labels. An intentional disconnect is a separate edit |
| Picks a capacitor then a supply pin and chooses **Decouples** | A named design relationship between qualified endpoints, including the return when known, with inherited or explicit preferences | Distance and side feedback during board placement, source navigation, and an explanation of the relationship |
| Draws a circuit using library parts and never explicitly groups or pairs anything | The same symbol, wire, label and pin facts as above | All geometric checks, library constraints and unambiguous rule matches run automatically. Ambiguous ownership appears as a suggestion with its evidence |

The proposed source form below is an extract, with the components and pin maps already declared. A designer using the canvas would see a selectable relationship from C17 to one pin of U3. This spelling uses ordinary bindings and named arguments. `decouples`, `pin`, `same_side` and `prefer_within` are proposed electronics vocabulary. Here 3 mm is a project preference chosen for the example. Production thresholds need an identified source and measurement convention.

```text
shared bypass_reach = 3mm
bypass = decouples(cap: C17.pin("1"), supply: U3.pin("VDD1"),
                   return_pin: U3.pin("VSS1"),
                   prefer_within: bypass_reach, same_side: "prefer")
```

A drawing command produces a typed edit against a document revision. It can add several declarations atomically, preserve comments and unaffected source, and update both panes from the accepted revision. Text edits run through the same checker. Undoing a pin reassignment restores the previous relationship in both views. Names resolve to occurrence-qualified pins; changing the displayed designator or symbol unit updates the source references through a checked rename. For graphics-generated bindings, retain a stable source key independent of the editable designator and never allocate a new key merely because a file reparsed. Arrays and repeated sheets need keyed instances where a reorder must preserve identity. Existing electrical objects must survive a symbol move, a sheet reorder and a PCB flip.

The editor also needs a policy for half-typed text. Keep the malformed source and its new span diagnostic. Keep the last valid picture explicitly tied to its revision. Independent well-formed scopes may advance when their inputs are known. Rebase a pending graphical edit only if its target and source preconditions still resolve. Grouped wires and a relationship must either commit together or yield an actionable conflict. Avoid regenerating an entire hand-authored file after a GUI gesture.

## Readability is a property of the drawn sheet

A netlist can tell us that two pins connect. It cannot tell us whether a person can follow the wire. Persist the drawing as typed sheet data alongside the electrical graph. Store wire polylines and attachment points, junctions and crossings, pin and port orientations, symbol/body outlines, text content/anchor/rotation, applicable font metrics and size, sheet boundaries, and any deliberate reading-direction or functional-group hints. Maintain readers from each visual object to the facts it affects. Text order in the file is independent of signal flow on paper. Imported schematics enter this same representation with their supplied coordinates and reliable electrical semantics. A netlist-only import yields connectivity with drawing coverage marked unavailable. [KiCad 10 schematic editor](https://docs.kicad.org/10.0/en/eeschema/eeschema.html)

| Check | Computation and evidence | Appropriate treatment |
|---|---|---|
| Obscured text or pins | Intersect oriented, transformed page-space text bounds and symbol ink with foreground labels, pin names, pins, or wires, using the resolved style at print scale. Handle intentional symbol graphics, pin labels and wire-label anchors explicitly. Highlight the offending spans and crossing area | Object-level warning. Coarse bounding boxes generate candidates. Refine against relevant glyph or line geometry before attributing a clash |
| Visually ambiguous connection | Compare the electrical junction and endpoint map with the visible dot, nearby crossing, and pin capture geometry. Highlight the two wires and show which nets they belong to | A crossing alone is legal. A floating endpoint that looks attached deserves a measured gap and the actual net on each side. An add-junction fix previews any merge |
| Signal hard to follow | Follow a named signal from driver to sinks through sheet ports. Count unexplained reversals, crossings, long detours, ambiguous label placements and off-page transitions relative to the sheet's chosen conventions | Give a finding on a specific path with a suggested location. Suppress the directional heuristic on feedback loops, bidirectional buses and power trees unless a local convention says otherwise |
| Functional block hard to read | For declared or suggested blocks, identify visually interleaved unrelated members, wires that repeatedly leave and re-enter the block, and repeated-channel instances drawn inconsistently | Prefer a concrete example with its path over a sheet-wide aesthetic score. A policy can disable or acknowledge a style finding without changing electrical status |

Evaluate in sheet units so zoom level, display DPI and pan cannot change a finding. Use a per-sheet spatial index for text and line changes and an adjacency index for path-based checks. A drag invalidates the old and new positions plus adjacent wires. Moving a net label that changes its electrical attachment is also an electrical edit. Style lint may advise. A proposed cleanup must preserve the electrical pin partition unless its preview explicitly presents an electrical edit. Hold locked symbols, manual bends and page boundaries fixed during any optional rearrangement. Track local suppressions by check, object identities and rationale so an incidental renumber does not lose them.

## Which parts belong together when the designer writes no code

Give a relationship its own type. A functional `group` describes related components. A directional `decouples` relation connects a specific capacitor terminal to a supply terminal and its return context. Other useful kinds include crystal and load network, regulator feedback divider and sense pin, termination and receiver, and protection device and connector. One object can participate in several relations with independent purposes. Schematic proximity can suggest members. Group membership alone cannot specify a pin-specific bypass or the right distance. Altium's documented flow from schematic classes to placement rooms is a precedent for carrying membership across the boundary. Pin-specific relations add information a room cannot express. [Altium schematic classes and rooms](https://www.altium.com/documentation/knowledge-base/altium-designer/creating-user-defined-component-classes-and-rooms-directly-from-the-schematic) · [Altium component clearance rules](https://www.altium.com/documentation/altium-designer/pcb/design-rule-types/placement)

1. **Start with facts the drawing already supplies.** Compile the pin graph, electrical roles, device-to-package mapping, hierarchical instance, sheet/block placement, and any library design guidance. A library can declare supply domains, paired return pins, capacitor roles or a reference-circuit template once. A designer placing that part inherits applicable checks automatically. Manufacturer or project rules retain source, units, metric, severity and applicability. A bare resistor or unannotated generic MCU still gets geometric checks.
2. **Generate explainable candidates.** For a decoupler, use a two-terminal capacitive device across compatible supply and return domains. Resolve candidate consumers and power pins in that occurrence and domain. Rank evidence from explicit library/template mapping, local topology and functional block. Diagram proximity is weak evidence. Keep capacitor arrays, bulk supply capacitors, regulators, several VDD pins on the same rail and multiple eligible consumers as distinct cases. A board location can help a designer inspect ambiguity. If a capacitor moves away, keep evaluating its established pairing instead of silently assigning it to the new nearest IC.
3. **Keep provenance and uncertainty visible.** Separate designer-confirmed intent, an applicable library rule, and an inferred suggestion. Deterministic inference runs automatically, explanations include the evidence, and competing candidates remain inspectable. A change to a symbol, net or library invalidates the relevant matches. Contradictory confirmed intent becomes a finding. Choosing a candidate on the sheet or board writes the same relation as the source example. Rejection can be remembered for that candidate and instance. Users can finish a drawing without confirming every suggestion.
4. **Measure the relationship the designer cares about.** On an unrouted board, measure the declared metric between the resolved pins' land anchors, say which two lands were chosen, and display layer side separately. A same-side preference is optional. Opposite-side placement immediately beneath a BGA can be deliberate. For routed guidance, report supply path and return path evidence, vias and missing plane information separately. A straight-line distance is a placement measure. A claim about loop inductance, bypass effectiveness or impedance requires its own model, inputs, and error bounds. [ST guidance on MCU power and decoupling](https://www.st.com/resource/en/application_note/dm00115714.pdf)

**A real example of what inference can know.** On the published Inkplate 2 PCB, nine capacitors have pads on both 3V3 and GND. U1 is the ESP32 module. Its supply pad 2 is at (122.410, 130.900) mm. The 100 nF C3's supply pad 2 is at (122.630, 133.100) mm. Both components are on the front. The pad-centre distance is 2.211 mm. A hypothetical +20 mm X move of just C3 makes it 20.339 mm. Those are measured facts and an exact consequence of the proposed translation. Whether C3 serves this pin, and whether 3 mm is the right preference, are separate questions. If a designer confirms the pairing and that preference, the canvas can say **“C3 is 20.34 mm from U1 pin 2. Your target is 3.00 mm. It was 2.21 mm before this move.”** Select the finding to see both pads, the measured line, and the source of the target. A shared rail on its own should never generate nine asserted bypass relationships. [Inkplate source board](https://github.com/SolderedElectronics/Soldered-Inkplate-2-hardware-design/blob/57c5179a669f5237cbca6a0c0cbc7aa936c7b1df/CAD/V1.2.3/Inkplate%202.kicad_pcb)

For “these parts overlap,” first identify which outlines and sides matter. Same-side courtyards can intersect while the bodies still clear. A front and back footprint can share XY space. Through-board leads, cutouts, mated connectors and tall bodies need their applicable Z extents or solids. Give the witness polygons or solid pair, side, applicable rule and overlap or gap. If a footprint has no valid courtyard or 3D model, show coverage for the available checks. A soft distance finding remains advisory during drag. Collision enforcement on commit follows the active rule policy. A group preference never silently relocates a part.

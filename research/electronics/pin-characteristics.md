# Datasheet characteristics and standard ERC

A symbol author can record a pull-up from IO to VDD, a 25 °C leakage measurement, and an absolute injection-current limit independently. A designer inspecting that pin can see which claim applies, under which conditions, and where it came from. The symbol, a pin, and each of its selectable functions can own any number of records. All three lists can be empty. The selected function contributes its own records alongside the base pin. Connector contacts can retain their manufacturer ratings while each placement declares the circuit's supply or signal role.

## Representation and evaluation

Each record has a quantity or state, rating class, ordered terminal references, and optional datasheet citation and note. Numeric records carry a dimension-checked unit and independently optional minimum, typical and maximum. Conditions use the same typed readings and may refer to other terminals. A library author can add a named custom state or measured quantity with an explicit unit. A named trace carries a typed sweep coordinate per point and shared fixed conditions, with separate minimum, typical and maximum data. The FET editor can show several traces on one symbol with distinct bias currents or temperatures. Ramp interpolation, safe-operating-area envelopes, programmable expressions and shared current-budget solving remain future work. The [example symbol library](../../examples/electronics/datasheet-characteristics.fg) includes a TI power MOSFET, an onsemi depletion-mode JFET, a TI matched dual JFET with bias-dependent noise spectra, and a separate illustrative configurable I/O.

The standard voltage rules compare unconditional operating and absolute bounds with voltage intervals from fitted providers. For a two-terminal voltage, the interval runs from the positive terminal's minimum minus the negative terminal's maximum to its maximum minus the other's minimum. Two terminals on the same resolved net have zero difference. A single-ended measurement uses the schematic voltage reference. Conditional records, typical-only data, and nets with unknown voltage appear as missing evidence for the voltage comparison. Placement-specific datasheet requirements can match a characterized point explicitly. The rule does not infer actual current from a pin's maximum rating or treat component ESD test data as system-level protection.

Installed Rust ERC libraries can request the `pin_specifications` input. Each fitted terminal contributes its occurrence ID, resolved net, symbol ID, selected function, and separate device, base-pin and selected-function records. Minimum, typical and maximum magnitudes are decimal strings paired with their unit to preserve small electrical values across JSON serialization. Batches are built when a loaded checker asks for them.

Altium Workspace component templates associate unit-aware parameters with a component type. KiCad 10 exposes a separate Simulation Model Editor with model-specific parameters and symbol-to-model pin assignments. ForgeCAD uses a repeatable datasheet record so a placement requirement can identify the measurement conditions and compare the specific manufacturer bound it needs. ## KiCad 10 basic ERC comparison

The comparison uses the versioned [KiCad 10 list of ERC checks](https://docs.kicad.org/10.0/en/eeschema/eeschema.html#list-of-erc-checks). Some errors arise at source elaboration in ForgeCAD, before a circuit exists for ERC.

| Check family | ForgeCAD behavior |
|---|---|
| Unconnected pins and no-connect flags | Checks unattached fitted pins and connected no-connect pins. A no-connect marker requires a named terminal. |
| Input driver and power source | One finding per resolved net and input class. Passive component terminals can satisfy the ordinary signal-driver check. Power inputs require a power output or a pin explicitly providing power/reference, including a connector placement with that assignment. |
| Output conflicts and pin types | Checks multiple push-pull or power outputs and selected function incompatibilities. KiCad's full configurable pin-pair matrix, including open emitter and distinct tri-state pins, remains a gap. |
| Label connection and spelling | Checks distinct names electrically joined, labels reaching fewer than two fitted pins, and case-only differences within a scope. KiCad also has dedicated single-global-label and power-pin-name spelling checks. |
| Wires and geometry | Wire endpoints are explicit references. The editor checks near misses and overlapping wire segments. Full ambiguous-junction, graphical off-grid, bus-entry and dangling graphic segment parity remains open. |
| Hierarchy, buses, multi-part symbols and annotation | Compilation validates endpoint and sheet port references, cyclic hierarchy and pin numbers. ERC covers shorted bus members, unplaced sub parts, differential mate conflicts and shorts. KiCad's bus-alias grammar, hierarchical label direction matrix and all shared-pin/value/footprint comparisons are not implemented. |
| Library, PCB and simulation consistency | Footprint and pad assignments have their own board handoff validation. Library-version comparisons, footprint-filter checks and simulation-model pin checks are distinct gaps. |

ForgeCAD additionally checks application intent, strap-derived attributes, same-address devices on the same SDA/SCL net pair, and declared pin voltage limits. Each new diagnostic has its own severity policy. An ordinary missing datasheet entry has no completeness finding.

The host now also compares guaranteed high and low logic levels, checks summed source and sink load on single-driver nets, and evaluates application-specific datasheet requirements. A requested resistance maximum at 4.5 V gate drive will not reuse a result characterized only at 10 V. The [example](../../examples/electronics/datasheet-review.fg) and [coverage protocol](rule-libraries.md) show both evidence paths.

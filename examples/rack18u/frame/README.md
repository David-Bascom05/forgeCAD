# frame: subsystem A, frame and rails

RACK-101 post, RACK-111 rail carrier, RACK-121 base pan, RACK-131 top pan, RACK-201 EIA rail (SPEC 5.1 to 5.4,
rev B with R1, R4, R7, R9), and the subassembly test `test.fg` (SPEC 9A).

## How each part is modelled

- **Post, rail.** The wider face is the base wall, sketched on `xz`, whose normal is -y. So the sketch plane
  is the outer face (v = 0 or q = 0), and the sheet lies behind it. The other leg is a `side: "down"` flange,
  turned to +y off the edge at x = 0, with its outer sharp on that edge.
- **Carrier, pans.** The base wall is sketched on `offset(xy, t)`, which puts the sketch plane on the inner
  face. The sheet runs down to z = 0, and the flanges turn up.
- **Points on faces.** A flange's sketch x runs from the base wall's top skin, not from the outer corner.
  Its y runs along the edge from the edge's start; a `bottom` face's y runs the other way.
- **Pan stud holes.** Each is sketched with `at:` a foot point on the floor, so it doesn't depend on where
  the trimmed flange's edge starts.
- **Anchors** are written as `anchor(plane(at:, normal:, x:))`. Each direction is a construction line in a
  sketch on a wall. Every anchor was checked by `probes/dump.py` against SPEC 5.
- **PEM anchors** are placement only (R1): no kind and no depth. The hw/ PEM parts carry the threads.
- **Anchor x axes** (SPEC R9, subsystem A's rule): x lies in the joint face and points toward the part's
  middle along its length, or toward the flange tip.
  ```
  post      stud_*[0], pnl_*[0..2], hng_*[0..1], stk_*[0..1]  x = +w
            stud_*[1], pnl_*[3..5], hng_*[2..3]               x = -w
  pans      stud_* x = +z; car_l x = -x, car_r x = +x; caster_* normal +z (R9), x = +x; hang[*] x = +x
  carrier   pan[i] x = +b; rail[k] x = +c
  rail      web_bot x = +r; web_top x = -r; eia[k] x = +r
  ```
  `tools/pairs2.py` (rerun after these changes) reports turn 0 on every pair.
- **Index pairs across the 180deg turns:**
  - BL.pan[i] -> base car_l[i]; BR.pan[i] -> base car_r[2-i].
  - TR.pan[i] -> top car_l[i]; TL.pan[i] -> top car_r[2-i].
  - The top pan's stud names are at the same pan-frame points, so its stud_fr_* meets post FL.
  - Rails: web_bot[0] is at the top on RF and LR (r runs -Z). On BR and TL the hole is rail[27 - k].
  - joints.fg checks every one of these.

- **Shop text.** Every part declares `shop: scs`, using `hw/shop.fg` copied verbatim.
- **Violations.** Zero typed shop violations: hole to bend, hole to edge, hardware edge, thickness, hardness.
- **Flat checks.** Every flat fits 762 x 914.4, every bend line is at most 1117.6, every bend is 90deg, and the
  box flanges carry their hardware at 30 (limit 76.2).
- **`expect volume`** is from drawing math, not copied from a run:
  - folded: legs (outer - r - t) plus a quarter annulus per bend, less the holes;
  - flat: the blank less the bend deduction 2(r + t) - (pi/2)(r + K t), less the holes.
  - Post, carrier and rail are within 1e-6. The pans are within 1% (corner trims and reliefs aren't in the
    sum).
- **Pans.** They build valid, with no FoldedTouch, and are mirror symmetric (8d1bb528). The build is 40 to
  120 ms, so there is no speed problem.

## test.fg results

The last full run is in out/test.json; render: renders/test-iso.png.
- **Overall:** ok, 310 instances, mobility 0.
- **Interference:** 0 at the default rails (100, 725), at (50, 750) and at (100, 400).
- **Thread fits:** 44 m6_thread pairs (min 4.78, SPEC rev B), none short:
  - 28 screw-into-S-M6-0 engage 5.23, the whole nut (12 carrier M6 x 12, 16 rail M6 x 10);
  - 16 FH-M6-20 studs into their nylocs engage 6.0.
- **Press fits:** 16 FH stud heads are covered by `fit_rule(pem_fh_m6_20.fg, post.fg)`.
- **EIA alignment, SPEC 8:** 39 anchor expects, 13 at each of the three rail positions. They check front to
  rear y, z across the flipped right rail and the rear rail at k = 0, 26 and 53, and x = -+232.55 (pitch
  465.10).
  - Each SPEC difference is written as both ends' absolute values (expect takes one metric).
  - Total 43/43 expects pass.
- **Rail position** is two shared params, `rail_front` and `rail_rear`, in the rails' poses. SPEC 6.3's
  anchor-index fallback isn't needed: the rail screws hang off the rail's web anchors, and the fit rule pairs
  them with whichever carrier nut is coaxial.
- **joints.fg:** ok, mobility 0, 62/62 expects. The frame is built only from its anchor pairs:
  - posts by `slider(.., along: -3.02)` on the base pan;
  - top pan on post FL;
  - carriers by `slider(.., along: 3.02)`;
  - rails `fastened` on carrier nuts k = 2 and 27 - 26.

  Each solved origin lands on its SPEC 5 pose, and every other pair is coincident or 3.02 apart.

## SPEC issues

1. **[R7, found by this test, applied]** At 716 long (y 42..758), each carrier end cut about 0.12 mm into the
   pans' inside bend. The floor is flat only from y 41.04 + 1.60 = 42.64. Forge reported "overlap
   (unconfirmed)" on all 4 carrier/pan pairs, and 1.32 mm3 each with the carrier lifted 0.01.
   - Now 714 long at y 43..757, with rail nuts at a = 19.5 + 25k and pan nuts at a = 57, 357, 657. The rack
     hole positions are unchanged.
2. **Stud and carrier pairs don't coincide.** 5.12 lists post.stud_* -> pan.stud_* and carrier.pan ->
   pan.car_* as fastened pairs, but they are 3.02 apart. R4 now joins them with sliders, as joints.fg does.
3. **Anchor x axes** were unspecified, and `fastened`/`slider` align x. A's rule is now R9. The post's upper
   panel and top hinge nuts were set to x = -w (coordinator's decision). R9's table was edited to match, with
   every turn 0.
4. **Caster anchors.** Their normal is +z (R9), not 5.2's original -z. 5.2 now says so, marked [R9], and
   the R9 revision notes it.
5. **Pan corner reliefs.** SPEC 4 says "4 auto corner reliefs". Forge now auto-trims the corners (t plus the
   shop gap, short walls trimmed) with a relief arc, the same at all four corners. That's fine for the
   frame.

## Forge gaps and bugs

1. **Box corner trim was not symmetric** (FIXED in forge-lang 8d1bb528). Repro: `probes/box_corner.fg`.
   - On a4149718, the corner between outline[1] and outline[2] trimmed 3.42 differently from the other three.
   - Now every corner takes the same trim: the short walls (front and rear) stop at x = +-289.02, and the
     side flanges run on to y = +-358.96 in the flat.
   - The pans are mirror symmetric, and their volumes and flat bbox are unchanged.
2. **`at` expects re-ran the whole assembly every time** (FIXED: now one run per param set).
   - Before the fix, test.fg took 425 to 990 s, nearly all of it in `at` expects.
   - Now it takes 1.6 s (`at_runs`: 2).
   - An `at` value taken from a loop variable (`at rail_front = pos[0]`) was ExpectUnevaluable; shared params
     work.
3. **Unfold bodies in assemblies.** The DXF needs `unfold()`, but then `part(..)` brings the flat body in as
   well, and it overlaps everything. Every frame instance uses `body: "<base wall>"`.
4. **Small grammar limits** (worked around):
   - an `expect` with an expression after `=` that contains `+` loses the tail (UnusedParam on its operand);
     put the value in a shared param;
   - `pi / 4 * 6.0 * 6.0` with bare numbers is a Ratio, not an Area; name the diameters;
   - no nested comprehensions and no integer division, so the rail's eia[k] uses a recursive `u_of(k)`;
   - the path `close()` after a final `tarc` back to the start is Degenerate (leave close out);
   - a path can't start with `tarc`.
5. **Expects compare one metric to a value**, so SPEC 8's differences, like y(a) - y(b), are written as
   absolute pairs.

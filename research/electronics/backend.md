### Findings that change the design

1. **The geometry used for a verdict matters at equality.** A KiCad 10 regression contains a through-hole pad whose true annular width is 0.1524 mm against a 0.1524 mm limit. Polygon approximation previously produced a false violation. A control pad with 0.1000 mm annular width must still fail. A robust backend needs explicit threshold semantics, decisive predicates and a witness. Adding a global epsilon can hide the control failure. [Stable regression](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/qa/tests/pcbnew/drc/test_drc_annular_overlap_issue24340.cpp#L87)
2. **One pad can imply several manufacturing operations.** KiCad 10 exposes primary, secondary and tertiary drill properties. Its CAM tests cover backdrilling the same via from both faces, ordering layers in drill filenames, and plated slots in ODB++. Altium documents controlled-depth drilling and distinct layer stacks in rigid-flex regions. One diameter and one through-hole flag would lose required information. [Padstack](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/padstack.h) · [CAM regression suite](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/qa/tests/pcbnew/test_cam_backdrill.cpp) · [Altium controlled-depth drilling](https://www.altium.com/documentation/altium-designer/pcb/high-speed-design/configuring-stackup-controlled-depth-drilling-back-drilling) · [Altium rigid-flex](https://www.altium.com/documentation/altium-designer/pcb/rigid-flex-design)
3. **Signal-path identity outlives a net boundary.** Altium lets designers constrain an xSignal between specific nodes across series components, and account for pin-package delay. The KiCad development tree has tests for trunk delay and bridging delay, including missing-terminal fallback. A sum of trace lengths per net cannot measure one receiver on a branched path. [Altium xSignals](https://www.altium.com/documentation/altium-designer/pcb/high-speed-design/xsignals) · [Package delay](https://www.altium.com/documentation/altium-designer/pcb/high-speed-design/xsignals/pin-package-delay) · [Development regression](https://github.com/KiCad/kicad-source-mirror/blob/f445174c99b83e40c0e7138501ce271017494dd6/qa/tests/pcbnew/net_chains/test_net_chain_trunk_delay.cpp#L133)
4. **Manufacturability can depend on intermediate construction.** The development via-stack provider inspects constituent spans, stack properties and hole aspect ratio. It distinguishes structural consistency from fabricator capabilities. A board can have a conducting path and still require a drilling or lamination process the selected fabricator cannot perform. The development tree also includes parity fixtures for creepage with slots and malformed outlines. [Development provider](https://github.com/KiCad/kicad-source-mirror/blob/f445174c99b83e40c0e7138501ce271017494dd6/pcbnew/drc/drc_test_provider_via_stack.cpp) · [Creepage parity cases](https://github.com/KiCad/kicad-source-mirror/blob/f445174c99b83e40c0e7138501ce271017494dd6/qa/tests/pcbnew/drc/test_creepage_engine_parity.cpp)
5. **An engineering change is a correspondence problem.** KiCad's updater reconciles netlist components with placed footprints. Altium documents component links, multi-channel physical identities and engineering change orders (ECOs). Altium also exposes a modification protocol for undo and editor synchronization. Importing a second schematic revision must preserve placed copper, component-specific overrides and user intent wherever correspondence can be established. [KiCad updater](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/netlist_reader/board_netlist_updater.cpp#L2046) · [Altium synchronization](https://www.altium.com/documentation/altium-designer/sch-pcb/keeping-synchronized) · [Altium PCB SDK](https://docs.developer.altium.com/ad-sdk-docs/guides/pcb-basics/)

## 1. Authority, identity and persistence

Use a project revision to bind several documents and library resolutions. Give persistent editable objects document-scoped stable IDs. Use compact arena indices internally with generations to detect stale handles. A published cross-document reference includes document ID, occurrence path and object ID. A user-visible reference such as J1 is an editable attribute. An imported UUID is a source mapping with format, source document and instance scope. Duplicate imported IDs produce an ambiguity diagnostic before any dependent bindings are made.

| Authoritative record | Important fields and relationships | Derived results |
|---|---|---|
| Project revision | Document revisions, library resolution lock, rule and process profiles, variant, units, file-format version | Dependency closure, reproducible job manifest |
| Logical design | Sheet definitions and instances, components, symbol units, pins, wires, junctions, labels, bus members, ports, no-connect markers | Instance-qualified pins, intended nets, ERC findings |
| Part definition | Immutable revision of logical pin set, symbol graphics, allowed packages, pin–pad map, ordering fields and optional simulation model | Resolved part and footprint for each occurrence and variant |
| Board | Stack regions, outline and cutouts, footprint occurrences, local overrides, layer artwork, route primitives, holes, zones, net ties and constraints | Effective layer shapes, spatial indexes, copper contact graph, ratsnest, fill, DRC |
| System assembly | Board occurrence and pose, connector definition and mating interface, harness occurrence, cavity map | Pin-to-pin system connectivity, cable endpoints and clearance results |
| Release job | Frozen inputs, requested outputs, variant, coordinate origin, file precision, fabrication profile and waiver set | Gerber/drill, BOM, placement, STEP, test netlist and digest of each output |

Store imported source coordinates and transformations explicitly at boundaries. Define one canonical board frame, a stack normal and thickness direction. Define the mirror axis for bottom-side placement, angle sign and placement origin. Apply exactly one transform at each boundary from pad-local to footprint-local to board to assembly. Repeated hierarchical sheets and two installed copies of the same PCB require separate occurrence paths even if their source UUIDs match. A pin with multiple electrical lands needs a one-to-many mapping. Preserve unnumbered mechanical pads and unplated locating holes without inventing logical pins.

Use integer nanometres as a proposed board storage unit. Parse decimal distances using checked integer conversion and explicit rounding at format boundaries. Specify coordinate limits before choosing wide intermediates: even a 128-bit cross product has an overflow boundary, especially for squared distances or products of determinants. Use the repo's exact-number fallback for ambiguous or out-of-range predicates. Rotation of a footprint about an arbitrary angle usually produces non-grid coordinates. Keep local geometry and the transform; define once where projection onto the manufacturing grid occurs. Round-trip tests must cover negative coordinates, reflections, a non-origin footprint anchor and non-orthogonal rotation.

Version documents and commands independently. Migrations produce a new revision, retain source IDs and record any lossy conversion. A library revision change is an explicit edit with a pin/pad/3D-model mapping preview. Persist zone outlines, settings, priorities and overrides. A saved fill may accelerate open if its provenance matches the inputs. Keep immutable evidence for releases even if a library later disappears. ## 2. Schematic compiler, libraries and synchronization

**Inputs.** Represent a wire as endpoints and segments, a junction as a deliberate connection, and a label as text plus scope and anchor. A bus has member identities and mappings; a bus entry alone cannot determine a scalar net name. A port on a child sheet binds to a specific parent sheet instance. Global power symbols, local labels, hierarchical ports and explicit no-connect marks have different resolution rules. Preserve unit ownership, hidden pins, stacked pins, pin electrical type, pin-swap and gate-swap eligibility, and the difference between a graphical pin location and the electrical hotspot.

**Compilation.** Expand the sheet-instance DAG while checking cycles. Resolve a library snapshot and units for each physical part. Index electrical anchor coordinates within each instance. Split wires at valid junctions and connect endpoint-on-wire cases under explicit junction semantics. Resolve labels and bus members within their scope, then hierarchical bindings and globals. Record the reason for every graph edge, such as wire contact, local label, parent port or power symbol. Emit equivalence classes of qualified terminals. Assign a deterministic display name and preserve aliases and conflicts. A net merge or split needs a provenance map from old to new membership; mint or retain stable net IDs using a documented policy and surface ambiguity to downstream constraints.

**ERC.** Run rule providers over the compiled graph and a configurable electrical pin-type matrix. Distinguish two push-pull outputs, legal open-collector sharing, power input without a declared source, a dangling wire, an explicitly unused pin, a missing sheet port and contradictory labels. Emit the implicated terminals, rule origin and a path that explains why the pins were treated as connected. Variants can change fitted state, properties and approved alternate parts. Keep a base electrical assembly and a variant-specific population projection. If an alternate changes pin mapping or package compatibility, require explicit resolution. Substituting a procurement part must not silently rewire the PCB. [KiCad schematic graph](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/eeschema/connection_graph.cpp#L762) · [ERC dispatch](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/eeschema/erc/erc.cpp#L2179) · [Variant unit regression](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/qa/tests/eeschema/test_issue24943_variant_unit_sync.cpp) · [Altium variants](https://www.altium.com/documentation/altium-designer/variants-in-design)

**ECO protocol.** Compare compiled logical intent, board revision, and the last accepted synchronization baseline. Generate typed operations such as add component, reassign pad net, replace footprint, change field, or retire occurrence. Each operation carries old value, proposed value, source and target IDs, preconditions, dependencies, and impact on tracks, rules and harness endpoints. Group dependent changes atomically. Preview both lost mappings and newly unconnected endpoints. Offer explicit reconciliation for missing or duplicate source IDs. Applying an accepted change twice should be a no-op or an explicit stale-base error. The next comparison must converge. Test reannotation, channel duplication, swapping a gate, changing pad numbers, local footprint edits and a concurrently modified board. [KiCad netlist updater](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/netlist_reader/board_netlist_updater.cpp#L2046) · [Altium component synchronization](https://www.altium.com/documentation/altium-designer/sch-pcb/keeping-synchronized)

## 3. Physical board, padstacks and fabrication process

Model a stack as ordered physical strata with stable layer IDs, material, nominal thickness and tolerances. Copper, dielectric, mask, paste and documentation layers have distinct roles. Track copper thickness, foil/plating assumptions, dielectric constant and loss tangent with frequency and provenance when known. A rigid-flex board partitions the outline into regions referencing sub-stacks. Validate overlap, gaps, layer continuity at region boundaries, bend lines, bend radii and permissible objects in bend regions. A track traversing a region boundary must encounter continuous physical copper. A 3D fold changes assembled placement while the flat manufactured coordinate system stays authoritative.

A **padstack** resolves by layer and use. Store copper shape and offset, anchor, rotation, shape overrides, drill geometry, mask and paste expansions, zone contact settings and suppression of unused lands. Include circles, oblongs, rounded/chamfered rectangles, custom unioned primitives and holes. A slot has a centerline, tool width and orientation. Distinguish nominal finished hole, fabrication tool diameter and plating allowance; some imported files only know one of them. Preserve that uncertainty. Footprint-local and board-local overrides need provenance and deterministic precedence. An antipad in an internal plane is a clearance result with net and layer context.

A **via structure** has one or more conductive transitions and associated process operations. Record nominal XY, start/stop layers, plating, hole shape, land by layer, drill side, depth target and tolerance, plugging/filling/capping and any secondary drill. A blind via ends on a specified internal layer. A buried via can depend on an earlier lamination stage. A stack of microvias has individual hops, shared landing pads and manufacturing constraints on staggering and filling. A backdrill removes a barrel segment; cutting past a required attachment is an electrical fault. Bottom-side depth is measured from the bottom process datum. Derive surviving conductive intervals after those operations, then intersect with layer attachment elevations. Keep this derivation inspectable.

For every drill group the CAM writer must answer: tool, plated status, origin, units, start side, physical span, process stage, and whether the feature is a hit, slot or routed profile. Test a through via with backdrills from both sides, offset slot, plated slot, nonplated hole inside a pad graphic, tented top and open bottom, and an unflashed inner land. Feature counts alone cannot catch a flipped start side. [KiCad padstack](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/padstack.h) · [KiCad 10 CAM tests](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/qa/tests/pcbnew/test_cam_backdrill.cpp) · [Altium layer stack](https://www.altium.com/documentation/altium-designer/pcb/defining-layer-stack)


## 4. Planar copper geometry and the ForgeCAD reuse decision

Define an effective-shape query with explicit purpose, layer, board region, revision and material state. Examples are conductive copper after drill removal, drill tool sweep, exposed mask opening, paste aperture, routing obstacle for a particular pair of nets, and component courtyard. A plated slot, mask opening, drill and copper land can all occupy different outlines. A generic bounding box is a candidate filter. The final predicate needs the relevant shape and purpose.

The minimum geometric vocabulary is points, finite line segments, circular arcs with orientation, stroked paths with cap/join definitions, disks, oriented slots, polygons with holes, islands and disconnected regions. Specify winding, treatment of coincident boundaries and self-intersections, box inflation, distance to a hole boundary, and exact equality at thresholds. Distinguish physical contact at a point from a manufacturable copper neck. Compute clearance witnesses as two points or overlapping subregions and a layer. Support full-circle arcs, near tangencies, same center/radius with opposite orientation and a through-hole subtracted from a custom pad.

ForgeCAD already has closed line/arc regions, arrangements, union/intersection/difference, offsets and exact predicates. Its Boolean implementation enumerates cross-operand piece pairs for intersections, then classifies and links pieces. The public result loops round constructed positions onto a binary grid. Exact decisions inside one operation and repeated conversion between that grid, board nanometres and CAM output grids have distinct error budgets. Preserve exact geometry or certified bounds across operations where a rounded intermediate could change a DRC verdict. Use specialized analytic distance predicates for common pad/track pairs. Broad-phase candidates should come from per-layer spatial indexes and expanded bounding boxes. For large pours test spatial partitioning, batching by connected spatial components and deterministic boundary stitching before committing to any single acceleration scheme. [ForgeCAD region Booleans](https://github.com/David-Bascom05/forgeCAD/blob/d9d93a0aa2e2cc3a915a9f8fcd96e2d192be9542/kernel/forge-cam-geom/src/boolean.rs#L152) · [Offset and grid](https://github.com/David-Bascom05/forgeCAD/blob/d9d93a0aa2e2cc3a915a9f8fcd96e2d192be9542/kernel/forge-cam-geom/src/offset.rs) · [Predicates and numeric preconditions](https://github.com/David-Bascom05/forgeCAD/blob/d9d93a0aa2e2cc3a915a9f8fcd96e2d192be9542/kernel/forge-math/src/predicates.rs) · [KiCad planar implementation](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/libs/kimath/src/geometry/shape_poly_set.cpp)

**Measured reuse probe.** I called the existing ForgeCAD Boolean routine with a 90 × 80 mm rectangle and disjoint 0.2 mm-radius circles at actual Koyomi via centers. Each sample was one rectangle-minus-region operation in a fresh process; the timer enclosed only the Boolean call. Counts refer to output boundary loops. Three runs per input on this cloud host, using an existing compiled library. The simplified outline, uniform radii and absence of thermals or touching traces make this a narrow probe. It verifies the loop-count result; it does not establish geometrical equivalence to a KiCad zone fill. The nanometre threshold regression above exercises a different failure mode.

## 5. Electrical connectivity, spatial indexes and incremental edits

Maintain **three different graphs**. Intended connectivity maps instance-qualified design pins to nets. The physical graph maps copper shapes on physical layers to connected components. A signal-path graph identifies terminals and traversable segments for delay, topology and tuning. A series resistor connects two nets for a particular signal-path measurement while preserving their separate net identities for DRC. An intentional net tie authorizes contact between specific nets only within a declared footprint region; retaining both net identities allows a second accidental short elsewhere to be detected.

**Physical graph construction.** Build shape nodes for copper pads, stroked track segments/arcs, via lands and filled zone islands per layer. Represent conductive barrel intervals as vertical edges between actual attachable layers. Use a spatial broad phase followed by per-layer contact predicates. Store a witness and reason on each contact edge. First collect observed contacts independently of assigned net so cross-net copper can be diagnosed. For open-circuit analysis group allowed contacts per intended net, respecting ties, isolation and explicit exceptions. A same-net pad overlapping an unplated hole has no conductive vertical path through that hole. A negative plane or cutout must first be resolved into actual copper.

**Local update.** For each edit collect old and new layer bounds, net memberships, stack spans and semantic references. Remove stale contact edges and query neighbors for the new shape. Union-find is useful for additions; deletion of a bridge can split a large component. Recompute affected components by traversal or maintain a deletion-capable graph, with a full rebuild as a reference. A physical contact can change even when net membership and bounding box are unchanged, for example a round land replaced by a hollow custom shape. A new rule can affect clearance across many nets; version that dependency separately from geometry. Derive airwires from unresolved connectivity. Airwire edge choice may vary under equal-distance ties, so compare component partitions independently of presentation.

**Concurrency.** Publish an immutable board revision and tag every graph, fill, DRC result and output with its input revisions. A move preview uses a private overlay. An accepted edit records before/after state, updates indexes and publishes one revision. If a worker finishes for revision 41 after revision 42 has committed, its result stays associated with 41. Cancellation leaves the last complete result available with its revision. Undo restores library mappings, effective layer geometry, exclusions and dependent results or schedules regeneration. The CLI, MCP and editor should submit the same typed commands. Preserve diagnostic reproducibility by sorting stable object IDs before publishing results from parallel workers. [KiCad connectivity engine](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/connectivity/connectivity_algo.cpp#L247) · [Board commit](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/board_commit.cpp#L189) · [Altium modification protocol](https://docs.developer.altium.com/ad-sdk-docs/reference/pcb/IPCB_ServerInterface/)

## 6. Rules, copper pours and sign-off

**Rule representation.** Compile expressions into a typed, bounded query language over board objects, pairs, layers, net classes, signal paths, regions and fabrication profiles. Each constraint has dimension, operands, directionality, qualifiers, minimum/preferred/maximum or an allowed set, precedence and provenance. A length supplied to a time constraint is a type error. Define symmetry for clearance(A,B), and preserve ordering for source-to-destination or aggressor/victim rules. Permit same-component, same-net, pair-member and explicit net-tie exceptions at the relevant scope. A bounded evaluator and precompiled predicates keep imported rule files predictable.

**Resolution.** Return the winning values *and the trace*: candidate rules, matched predicates, ignored lower-priority values, hard process floor and unresolved conflicts. Specify how bounds combine for each constraint family. For example, a designer's 0.15 mm preference and a 0.18 mm fabricator minimum imply at least 0.18 mm for a manufacturable route. A preferred 0.15 mm value is then infeasible. A project with contradictory hard min and max should get a diagnostic at rule compile time if possible. Imported KiCad/Altium priorities require a compatibility mapping or an unsupported-rule finding. Never silently reinterpret source precedence. Cache using revision, rule family, both objects and layer plus the dependencies actually consulted. A same-net shortcut valid for copper clearance may be invalid for drill-to-drill clearance. [KiCad rule evaluation](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/drc/drc_engine.cpp#L1014) · [Altium Constraint Manager](https://www.altium.com/documentation/altium-designer/sch-pcb/constraint-manager)

**Pour algorithm.** Resolve board material and cutouts for a layer. Clip the requested zone to that domain. Query nearby obstacles using the largest applicable clearance or a conservative upper bound. Subtract inflated foreign copper, keepouts and higher-priority conflicting fill. Resolve direct versus thermal connection per pad and zone. Construct spoke candidates from width, angle, gap and anchor, then confirm each surviving spoke really touches both pad and surviving pour. Enforce minimum neck and island policy. Recompute affected island contacts and retain the final per-layer artwork and its provenance. Define deterministic handling for same-net zones, equal priorities, interacting thermals, isolated islands, solid versus hatched fill and conflicts. If a fixed-point pass is used, specify termination, detect cycles and publish an unresolved finding on failure. Invalidate downstream lower-priority zones when a higher-priority one changes. A changed spoke can disconnect distant copper within the same island; a bounding rectangle alone cannot bound the graph impact. [KiCad fill](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/zone_filler.cpp#L446) · [Altium polygon behavior](https://www.altium.com/documentation/altium-designer/pcb/signal-layer-polygons)

**Check providers.** Deliver separate check families for shorts and opens, copper clearance, copper-to-edge, neck width, drill clearance, annular ring, slot breakout, mask slivers, paste openings, via span and aspect ratio, keepouts, component courtyards and heights, differential geometry and path timing. Later add reference-plane discontinuities, return-path vias, creepage and rigid-flex constraints. Creepage asks for a surface path around obstacles or slots under specified rules; a 2D closest-point clearance answer solves a different measurement. Define boundary inclusion and certification per provider. A result includes rule revision, severity, numerical limit, measured value or bound, evidence geometry, layer, implicated objects and reproducible ID. Store waivers by stable IDs and applicability conditions; changed geometry or material can invalidate a waiver. Report unsupported checks and incomplete evaluations alongside pass/fail. A release policy decides which ones block manufacturing.

**Online and full checks.** The fast path predicts violations near proposed edits. Full DRC operates on a consistent, fully poured snapshot and reports the rule/profile identity and checker coverage. Both paths use the same shape and rule semantics. Exercise rule edits without geometry edits, old violations disappearing, an out-of-date fill, copper exactly on the limit and 1 nm either side. Compare incremental and full results after every command in randomized edit/undo sequences. [KiCad DRC dispatch](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/drc/drc_engine.cpp#L919) · [KiCad copper checks](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/drc/drc_test_provider_copper_clearance.cpp) · [Altium DRC](https://www.altium.com/documentation/altium-designer/pcb/drc/setting-up-running)

## 7. Interactive routing, tuning and electrical models

The router consumes a board-revision snapshot, effective obstacles, applicable rules, legal layer transitions, locked items and terminal targets. Its transient state includes a route head, fixed tail, posture, layer, width, rule context and changed obstacles. Start with manual geometry plus legality queries; then add obstacle walkaround, shove, drag, differential-pair placement, via transitions and tuning. For each cursor update, query an expanded spatial corridor, construct candidate centerlines and swept copper, evaluate exact clearances near obstacles, and score candidates for length, bends, vias and disruption. Give stable ties a deterministic order. Bound shove recursion and latency. A blocked gesture returns the conflicting object and rule. Cancel drops the private changes. Accept atomically writes replacements and preserves UUIDs for moved pieces wherever correspondence exists. Replay identical pointer/command streams against a known snapshot in CI. [KiCad router branching](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/router/pns_node.cpp#L157) · [Commit path](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/pcbnew/router/pns_router.cpp#L842) · [Altium interactive routing](https://www.altium.com/documentation/altium-designer/pcb/routing/interactive)

Differential pairs need member identity, polarity, coupled gap, width profile, permitted uncoupled length, skew tolerance, neck-down regions and via-pair rules. Check each physical trace against neighbors and the relationship between the pair. At fan-out, the permitted uncoupled segment is terminal- and rule-dependent. Represent tuning patterns parametrically with anchors, target, envelope and ownership of generated segments so an undo or re-tune does not duplicate copper. Recheck crosstalk/spacing and topology after a meander edit. Include a regression where dragging a pair through a pad preserves the selected width and pair polarity. [KiCad width regression](https://github.com/KiCad/kicad-source-mirror/blob/e432beac2668303194ba2040274f9e5efe773fc0/qa/tests/pcbnew/test_pns_diff_pair_tuning_width.cpp) · [Altium differential routing](https://www.altium.com/documentation/altium-designer/pcb/high-speed-design/interactively-routing-differential-pairs)

For timing use an explicitly traversed path. Sum straight lengths and arc radius times swept angle, vertical travel between actual attachment layers, and approved component bridges. Add per-layer or per-profile propagation delay and terminal/package delays exactly once. Keep lengths, time and impedance distinct types. A via's unused stub can affect signal integrity while contributing zero series path travel beyond the attachment. In a branched topology state which receiver, branch, trunk or aggregate is constrained. Ambiguous endpoints produce an indeterminate measurement. Unknown dielectric data should yield a geometric length and a clearly qualified delay estimate. Impedance requires trace geometry, copper thickness, return reference, dielectric parameters and assumptions about mask and coupling. An empirical profile, quasi-static cross-section solver and full-wave simulation have different validity ranges. Pin model parameters, frequency and solver method in any reported result. ## 8. Output, interchange and physical assembly

**Manufacturing job contract.** Freeze revision, resolved libraries, stack and copper weight, variant, origin, rotation/mirror, drill convention, precision and supported output features. Resolve or reject stale fill. Emit a manifest tying each delivered file to the inputs, generator revision, physical layer and process step. Publish the directory or archive atomically after all writers succeed. Run an independent readback of actual output geometry. Counting written objects cannot detect a negative plane rendered with reversed polarity, an inch/mm error, or a bottom-side mirror.

| Output | Data it must consume | Independent verification |
|---|---|---|
| Gerber copper, mask, paste, legend, profiles | Ordered layer image, flashes/strokes/regions, positive and negative polarity, aperture definitions, stable object/net attributes, final origin and precision | Parse with a separate implementation; compare occupied regions under a declared chord and quantization budget. Check feature witnesses at pad center, hole, thermal gap and clearances. Test polarity order. |
| NC drill, slot and route | Tooling operations grouped by plating, span, side and depth as supported by the delivery format; map and human-readable stack instructions | Normalize units/origin and compare sorted tool, hit, slot and group records. Reject a job that requests controlled-depth drilling without any artifact conveying depth. |
| Electrical test netlist | Testable pads, vias, net identity, side and position, probe-access policy | Reconstruct connectivity from emitted copper plus plated drill spans and compare pad partitions with intended nets. Expose expected net ties and process features that the verifier cannot reconstruct. |
| BOM and placement | Physical instance, approved parts, fitted state, alternates, side, centroid convention, placement rotation, supplier IDs and variant | Count fitted items per part; match each position record to exactly one physical component. Verify bottom rotations using an asymmetric footprint under a known origin. |
| STEP and assembly | Finished board geometry, chosen model revision and transforms, component envelopes, selected detail recipe, independent mating anchors | Compare fiducials, connector mating plane, hole axes and bounding geometry across source revisions. Regenerate with vias suppressed and confirm the drill and netlist outputs retain them. |
| Rich manufacturing exchange | Stack, padstacks, nets, components, profiles, assembly and process metadata within the selected IPC-2581 or ODB++ dialect | Compare a semantic inventory after independent readback. Declare which optional constructs and revisions the exporter supports. |

Gerber is an image description with attributes. Excellon and related drill conventions carry different information. A bare set of copper polygons cannot, on its own, recover intended logical pin names, plating stages, component variants or all net-tie permissions. Native document persistence, interchange and manufacturing are separate contracts. **Mechanical and harness boundary.** Treat an electrical connector terminal, footprint pad, physical cavity and 3D mating datum as four referenceable entities. A connector with four signal contacts, two shield tabs and two locating pegs makes the need apparent. Build transforms through board occurrence and connector body to harness frame. Resolve a persistent cavity reference into a temporary harness index at solve time. When a replacement package loses a cavity, mark the endpoint unresolved with its previous identity. A nearest-point repair could quietly swap power and ground.

For system checking, map board ports to connector cavities to wire terminations to the mating board ports. Provide checks for unconnected contacts, intentional opens, crossed pairs, swapped polarities, shield termination, wire gauge/current compatibility when rated data exists, and mechanical mating incompatibility. Keep board-net names local to a board occurrence. Mating two visually identical boards can connect different logical nets by design. A library mating model carries the explicit mapping. Simplify should publish regenerated bodies alongside externally owned datums and correspondence records. A missing decorative STEP model can still leave a fully defined electrical pinout and mate frame. ## 9. Worked acceptance case

Build a four-layer fixture with L1 signal, L2 ground, L3 power and L4 signal. Populate a two-channel hierarchical schematic, a series resistor in each channel, a shared keyed connector, a ground zone and two mounting holes. Place two copies of the board in an enclosure. Use explicit stack elevations and a known terminal mapping. This is a proposed verification case. The following outcomes can be checked before an editor exists.

| Operation | Required observable result | Failure this distinguishes |
|---|---|---|
| Instantiate the second schematic channel | Distinct qualified component IDs and local nets, shared globally named supply | Collapsing channels by source symbol ID |
| Reannotate the connector from J1 to J7 | ECO updates its display designator; placement, tracks and harness bindings survive | External references keyed by printed name |
| Route 18 mm on net A and 22 mm on net B across a designated resistor bridge | Copper connectivity returns two nets; the designated endpoint path reports 40 mm planar copper plus separately identified allowances | Net-short hacks used to implement timing |
| Change one 10 mm portion from 6 ps/mm to 7 ps/mm, all else fixed | Path delay increases 10 ps; physical copper length stays the same | Using length as the sole delay cache key |
| Remove a bridge trace segment, then undo | Same pin assignments, one new open if there is no alternate path, restored partition after undo | Union-only connectivity under deletion |
| Backdrill an unused via stub from the far face | Drill grouping acquires a secondary operation; contacted signal layers stay connected. Overdrilling past one attachment raises a fault | Modeling every via as an unconditional through connection |
| Flood a GND pad with four thermal spokes; remove copper through all four | Pad is disconnected from the pour unless another conducting route exists. Show the failed spokes and island policy | Treating “thermal configured” as proof of contact |
| Reduce clearance by one stored unit beside an exact-limit arc | The rule witness crosses the stated acceptance boundary; mirrored and rotated copies yield the same physical judgment within the specified transform policy | Tessellation-driven sign-off and unit drift |
| Change a resistor to DNP in variant B | Bare-board copper and drilling remain identical when the variant changes only fitting; placement/BOM change by the specified release policy | Applying assembly options to fabrication layers |
| Change one connector cavity designation with the board installed twice | Both occurrences identify the changed library binding; only affected terminations require review | Shared source IDs collapsing assembly occurrences |
| Launch fill, undo the triggering move, then let the worker complete | Results of the abandoned revision never become the displayed or released fill | Stale asynchronous publication |
| Simplify both boards in the enclosure | Connector datum, physical pin map and drill release still point to original engineering objects | Attaching semantics to disposable 3D faces |

## 11. Verification, scale and sequencing

A zero-dependency build still permits external reference engines in verification. Keep fixtures, normalized expectations and provenance distinct from production code. Independent checks should record executable version, project settings, library closure, fill state, rule profile, enabled providers, overrides and output precision. Missing libraries or custom rules can change baseline findings. KiCad, Altium where a licensed test environment is available, independent CAM readers and fabricated test coupons provide different kinds of evidence. A disagreement is a triage case. Record both witnesses and determine which semantic contract each tool used.

| Test level | Inputs and exact assertion |
|---|---|
| Primitive and threshold | Tangent arcs, coincident segments, hole in pad, 1 nm sliver, arc crossing tile boundaries, mirrored custom pad; compare topology, numeric interval and boundary decision |
| Metamorphic | Translate/rotate/mirror valid boards; reorder source records, renumber imported nets, split a straight track into two; preserve qualified pin partitions and physical measurements under the specified transform |
| Incremental parity | Seeded sequences of insert, move, delete, pour, rule edit, library update and undo; compare with fresh compile/fill/DRC at chosen revisions. Also run with different worker counts |
| Document and compatibility | Save/reopen, migrate old revision, exercise unknown features, missing libraries, duplicate IDs, stale generated assets and alternate packages; return diagnostics with source positions |
| Route replay | Replay accepted, canceled, blocked and backtracked gestures, including locked obstacles and differential-pair layer changes; compare legal final geometry, IDs and delta/undo behavior |
| Release readback | Reconstruct per-layer artwork and drill spans, compare physical connectivity, count variant-specific placements and check known dimensions and mating frames |
| Stress | Dense BGA escape, zone with thousands of islands, heavily branched supply, repeated schematic hierarchy, two large installed PCBs. Record peak memory, cache rebuild counts and cancellation latency |
| Physical confirmation | Fabricate a small coupon containing annular limits, differing slot types, known calibration dimensions and connector orientation; compare CAM prediction, electrical continuity and mechanical fit |

The [per-frame performance gates](live-checks.md#performance-gates-that-can-change-the-product) define the reference workloads, per-provider and end-to-end clocks, percentile targets and complete-verdict coverage. Use those gates throughout development, starting with the first editable graphical fixture.

**Dependency order and exit criteria**

Begin each increment with its graphical/textual authoring equivalence, applicability and typed failures, proof ledger rows, cold oracle, and drag replay. The [end-to-end acceptance scenario](design.md#first-acceptance-test) is the first vertical slice.

1. **Document, IDs, transforms and import.** Parse a versioned KiCad corpus, reload native files and reproduce hierarchy, pin/pad bindings, board inventory, drill records and cross-document identities. Produce an explicit loss report for unsupported constructs. Stable IDs and frame conventions gate all later work.
2. **Copper and independent connectivity.** Build effective shapes, layer indexes, physical clusters and the full-rebuild reference. Reproduce shorts, opens and net ties through edits and undo, including holes and blind vias. Deliver a headless witness query.
3. **Schematic compiler, ECO and rules.** Resolve multi-instance schematics and libraries; preview/apply an ECO against an edited board. Compile scoped rules and explain trace-length, clearance and process-floor resolution on conflicting examples.
4. **Fill, sign-off and basic fabrication.** Generate thermal and solid zones, clearances, drill groups, Gerber, BOM, placement and test-netlist outputs for a bounded rigid-board feature set. Pass independent CAM readback and build a coupon. Publish a precise supported design envelope.
5. **Interactive routing and system integration.** Profile a speculative router with replay tests, then add shove, paired traces and tuning. Resolve board connectors to both installed assemblies and the harness. Moving a connector invalidates pin positions and keepouts while preserving the correct cavity bindings.
6. **Advanced processes and analysis.** Qualify rigid-flex, HDI lamination, backdrill and electrical timing against process-specific fixtures. Backdrill semantics belong in the schema from the start; shipping a qualified exporter for each process is a separate milestone. Budget field-solver validation, simulation models, procurement/library curation and proprietary interchange as independent programs.

**Open decisions that affect feasibility.** Which rigid/HDI/flex process families must the first fabrication release certify? What minimum set of custom KiCad rule semantics must survive read–edit–write? Which edited-library conflicts require user resolution? What constitutes an acceptable approximation for a curved feature exactly at a limit? Which net ties and series devices can be traversed under which measurement modes? What evidence is required before accepting a manufacturer-specific timing or impedance profile? The fixtures above make these questions testable without committing ForgeCAD to a UI or a third-party production dependency.


## Appendix A. Public backend operations and failure contracts

These are proposed logical interfaces. The names describe required behaviors and leave Rust crate boundaries open. Each response carries the input revision and explicit completion status. A caller can request a cheap approximate preview, an engineering measurement with a bound, or a release-qualified result. The backend must return the achieved quality.

| Operation | Inputs | Result and invariants |
|---|---|---|
| ResolvePart | Library lock, component occurrence, variant, library override set | Resolved unit, symbols, footprint, pin–pad map, model reference, missing/ambiguous bindings. Report local override conflicts field by field. |
| CompileLogical | Schematic root, sheet instances, rule profile, changed object set | Qualified terminals, alias sets, intended-net partition, ERC evidence and net split/merge map. Deterministic full and incremental outputs. |
| PlanECO / ApplyECO | Compiled revision, board revision, last sync revision, link decisions | Ordered change set with preconditions and orphan consequences. Apply atomically against the same base or return explicit stale inputs. |
| EffectiveShape | Revision, object, layer, region, purpose and process stage | Analytic shape or region, coordinate frame, error bound, provenance and dependency list. Unknown required input is a typed result. |
| ExplainContact | Revision, object pair, layer or via interval | Witness geometry, conductive path or gap, net assignments, and tie exception where applicable. Include both physical contact and applicable electrical interpretation. |
| ExplainRule | Constraint type, objects, layer, variant, fabrication profile | Typed min/preferred/max or allowable set, rule provenance, evaluation order and conflicts. Surface undefined measurement inputs separately from a numerical failure. |
| BeginRoute / Preview / Accept | Board revision, terminal, intent, cursor, mode and locked items | Overlay revision, candidate segments/vias, moved items, clearance witnesses, latency and cancel handle. Accept returns one durable delta or stale base. |
| Refill | Snapshot, selected layers/zones, dirty dependency closure, cancellation token | Revision-tagged final copper and islands, affected connectivity and fill diagnostics. A canceled job publishes no partial sign-off snapshot. |
| MeasurePath | Explicit endpoint pair and occurrence context, topology/branch policy, stack and timing models | Ordered traversal, per-segment length/time contributions, uncertainty and missing inputs. Multiple possible traversals are visible to the caller. |
| RunChecks | Immutable revision, check families, policy, rule closure and waiver snapshot | Findings, coverage, measured bounds, incomplete providers, and evidence. A zero-length finding list with skipped required checks cannot produce a qualified pass. |
| BuildRelease | Immutable manifest, required checks and target job set | Output bundle, digest and verification record, or a typed failure identifying the affected output and feature. Identical inputs give identical normalized manufacturing semantics. |

**A library example that warrants an independent type.** LibrePCB makes the device the explicit association between a generic component, a package and a signal-to-pad mapping. Altium documents updating placed footprints from libraries and reconciling local changes. Consider two SOT-23 transistors with the same copper geometry and different pinouts. Package equality permits mechanical reuse; replacing one device with the other requires an electrical mapping review. A component name, footprint name and STEP mesh cannot encode that distinction. A test should replace the device while holding the package geometry constant and assert a pin-map ECO, a changed connectivity expectation, and an unchanged body envelope. [LibrePCB library semantics](https://librepcb.org/docs/quickstart/create-library-elements/) · [Altium footprint updates](https://www.altium.com/documentation/altium-designer/pcb/placing-components/updating-footprints-libraries)

**A rule-precedence example.** Suppose a board has a global copper clearance, a class-to-class power clearance, and an exception around one connector's pads. Import rule priority, pair scopes, layer scope, and exemptions with the document. In a compatibility test, pick two traces, a trace–pad pair on the connector and a geometrically identical pair on another layer. Evaluate each pair in both argument orders for a symmetric clearance rule. Store expected rule identity as well as value; two rules with identical thresholds can diverge after the next project edit. Verify a change to the pad's class invalidates the cached decision while leaving unrelated classes reusable. Altium documents scoped unary and binary rules and priority. The native resolver also needs a policy for reconciling imported design intent with the selected fabricator's hard limits. [Altium scoping and priority](https://www.altium.com/documentation/altium-designer/pcb/defining-scoping-managing-design-rules)

**Capability boundaries.** Schematic simulation export needs simulator pin order, model associations, subcircuit parameter binding, units and model provenance. Signal integrity needs return paths, frequency-dependent material and loss data plus a validated solution method. Power integrity needs source and load conditions, conductivities, temperature assumptions and mesh convergence checks. An autorouter needs a search objective and a legality oracle, and may leave nets unrouted. Component sourcing needs supplier data, revisions, availability dates and alternates. These services can consume the same versioned design; ERC, DRC and connectivity have distinct correctness criteria that remain independently testable.

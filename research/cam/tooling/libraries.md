# Machine-readable vendor tool libraries

David's ask (via the coordinator, 2026-11-24): instead of extracting tools one PDF at a time, find
openly downloadable maker tool libraries in machine-readable formats and import them in bulk,
recording each download's terms. Rules: maker-hosted (or Autodesk-hosted with the maker named),
no sign-up, login, email form or bot-challenge bypass.

## Fusion JSON structure (sample tools)

The top level is `{"data": [tool, ...], "version": N}`. N is 33 to 37 in these files; IMCO Imperial uses 3. A `.tools` file is a zip that holds `tools.json` with the same structure (as in RobbJack's file).

Milling and drilling tool, Garr EDP 21265 (18.50 mm 3xD drill):
```
{"type":"drill","unit":"millimeters","vendor":"Garr Tool","product-id":"21265",
 "product-link":"https://www.garrtool.com/product-details/?EDP=21265","BMC":"carbide",
 "description":"18.50mm 3xD DIN 2FL H/P DR *AlTiN-based*","guid":"...",
 "geometry":{"DC":18.5,"LCF":79,"LB":131,"OAL":131,"SFDM":20,"NOF":2,"SIG":140,"HAND":true,"CSP":false,
             "shoulder-diameter":18.5,"shoulder-length":81,"assemblyGaugeLength":131},
 "shaft":{"segments":[{"height":2.799,"lower-diameter":18.5,"upper-diameter":20}]},
 "post-process":{"number":0,"turret":0,"diameter-offset":1,"length-offset":1,"live":true,...},
 "start-values":{"presets":[{"name":"Default preset","guid":"...","presetGuid":"...",
     "n":0,"n_ramp":0,"v_c":0,"f_z":0,"f_n":0,"v_f":0,"v_f_plunge":0,"v_f_ramp":0,"v_f_leadIn":0,
     "v_f_leadOut":0,"v_f_retract":0,"v_f_transition":0,"tool-coolant":"flood",
     "use-feed-per-revolution":false,"use-stepdown":false,"use-stepover":false,
     "material":{"category":"all","query":"","use-hardness":false}}]}}
```
- **Geometry keys** seen across the libraries (ISO 13399-like): DC (cutting dia), LCF (flute length), LB (body length below holder), OAL, SFDM (shank dia, i.e. dcon), NOF, RE (corner radius), SIG (point angle), TA/TA2 (taper angle), TP (thread pitch), NT (number of teeth/threads), DCX, CSP, HAND, `shoulder-diameter`, `shoulder-length`, `tip-diameter`, `tip-length`, `tip-offset`, `thread-profile-angle`, `upper-radius`, `profile` (form tools), `assemblyGaugeLength`. Holders are stored in a separate `holder` object (mill holders as `type:"holder"` records with `segments`).
- **Turning tools** (Sandvik, Iscar, Kennametal, Tormach turning): `geometry` = {INSD, SC (insert shape), SCTY, TC, S, RE, RA, OAL, LH, `tool_grooveWidth`, `tool_insertWidth`, TP/TPN/TPX and `thread-*` for threading, `3DGeometry`:{fileName:"<holder>.stp", id}} plus `holder`:{H, W, LH, OAL, HAND, MTP, THSC, `tool_roundShank`} and `setup`. The referenced holder STEP file is **not** inside the plain .json download.
- **Presets** (`start-values.presets[]`): name, description, v_c, n, n_ramp, f_z, f_n, v_f, v_f_plunge/ramp/leadIn/leadOut/retract/transition, stepdown (ap), stepover (ae), use-stepdown, use-stepover, ramp-angle, tool-coolant, use-feed-per-revolution, use-constant-surface-speed (turning), material{category, query, use-hardness}. Example from IMCO metric: `{"name":"N - Aluminum Alloys - Slotting","n":11353,"v_f":413.25,"stepdown":1.5,"stepover":3,"v_c":0.0182,...}`. The IMCO `v_c` values look mis-scaled; derive cutting speed from n and DC. Many libraries ship a single "Default Preset" with every value 0; the "cutting data" column shows which ones do.
- Autodesk also publishes the schema: `libs/Autodesk_schema/tooling_json_schema/JSON Schema.zip` (from https://cam.autodesk.com/tools/tools/Tooling%20Schema/JSON%20Schema.zip, 4.5 MB). It contains FusionToolLibrarySchemas.html, sample libraries, a sample 3D turning holder and an xlsx template.

# Review: hosted/server-hardening @ 266a07f3 (N1–N9), by HOSTED-DESIGN, 2026-11-25

Built and tested here: `cargo build --release -p forge-server -p forge-sync -p forge-remote`
is clean, and `cargo test --release` on the three passes (40 tests). None of the tests exercises
the new paths: closing, a reopen during close, N8, N9. Findings below were found by reading the
code end to end. Each gives the path and a concrete scenario.

## High

**H1. Ops sent during a document's close are dropped, and the client never resends them.**
`hub`, `Ev::Up`: a connection whose Join sits in `closing[doc].joins` has its `Up`s sent only
to `docs.get(doc)`, which is None while the document closes, so they are dropped silently. The
client (`forge-sync/src/client.rs` `reconnect`) sends Hello and then its pending ops right
away, not after Welcome, and `receive(Welcome)` does not resend them. Scenario: one person
editing, their connection drops (members 0, so the actor starts closing: checkpoint,
snapshot), and they reconnect within the save window. Their pending ops never reach the
server and stay pending until the next reconnect; if the app is closed first, they are lost.
N1 introduced this: before it, the close was synchronous, so an Up after a Join always reached
the new actor in order. Fix: queue the conn's Ups with its Join in `Closing` (one ordered
`Vec<DocEv>`) and deliver them in order to the new actor. Also make the client resend pending
ops on Welcome; the server's dedup makes that idempotent, and it is the robust fix.

**H2. A Close lost on a full inbox leaves a zombie actor and the document stuck.**
On the last Leave, `d.tx.try_send(DocEv::Close)` can fail on a full inbox (`DOC_INBOX` 1024).
The comment says dropping the handle "still ends the actor", but it doesn't: the actor holds
`self_tx` (a clone of the same sender, also handed to hash-build threads), so its
`recv_timeout` never sees Disconnected. The actor runs on with no members, and
`closing[doc]` is never removed, so every later join waits forever (then "too busy") until a
restart. Fix: a `closing: Arc<AtomicBool>` shared by the handle and the actor, checked on every
loop turn (the 200 ms timeout already wakes it); or give builds their own channel so the actor
holds no sender of its own inbox.

**H3. `ended()` gives up after 60 s, with the same outcome as H2.** If the hub's inbox stays
full for 60 s, `Ev::Ended` is never delivered, so `closing` or `docs` keeps a dead generation
forever. N3/N4 guarantee the hub never blocks on an actor, so the actor can safely block on
`hub.send(ev)`; with that guarantee there is no deadlock. Use a blocking send, and say why in
a comment.

## Medium

**M1. Snapshot-on-close deletes the document's op history.** `FileLogStore::compact` rewrites the
log as just the snapshot (`fsx::put` of the "first" record). N1 now compacts on every close
where seq > floor, so each time the last person leaves, the microversions since the last
compaction are gone: who changed what and when, and the per-op history DESIGN §5 keeps ("the
op seq is the live history ... the op log stays"). Phase 1 still writes forge-history commits
at checkpoints, so versions survive at checkpoint granularity, but ops do not. Fix: a
snapshot is a record (seq, text, seen) appended to the log or kept beside it; open reads from
the latest snapshot record, and nothing is deleted. Retention (dropping ops older than X) is a
separate, explicit policy. This is the Postgres design too (DESIGN §17.1: `snapshots` rows,
`ops` kept).

**M2. N8 drops a Resync instead of deferring it.** `connection`: a second `Resync` within
`RESYNC_GAP` is `continue`d away. The client sends one Resync per detected divergence
(`client.rs` `diverged`). If the first snapshot still leaves it diverged (e.g. an op committed
in between) and the doc then goes quiet, nothing triggers another, and the client stays
diverged on an idle document. Fix: remember one deferred Resync per connection and send it when
the gap ends, or answer with a refusal the client retries on.

**M3. N5/N6: the dedup keys grow with accounts, and every snapshot now carries all of them.**
The cap is 10,000 keys per account, and every snapshot (now on every close) writes
`self.seen` whole, at ~40 B a key: about 400 KB per active account per document per close. In
Postgres the question disappears: `unique (doc, client, op_id)` on `ops` answers a retry by an
index lookup (0.03 ms p50 in the phase-2 smoke run, `bench/phase2_pg.py`), with no in-memory
set and nothing in snapshots. For the file store, op ids are per-client monotonic
(`client.rs` `next_id += 1`, sent in order), so a per-client high-water mark plus that
client's refused ids above it gives exact answers in O(clients). A bare high-water mark would
answer "already committed" for a refused id below it, so the refused ids must be kept too.

## Low

- **L1.** `Ev::Ended.why.contains("quarantined")` is a typed fact carried as a string; a
  wording change silently stops quarantining. Use an enum (`Ended::Normal | NeverOpened(why) |
  Quarantined`).
- **L2.** `Shared.abandoned` (per document name) is never pruned: one entry per document ever
  opened, forever. Drop an entry when its count is 0 and no actor exists.
- **L3.** `Timed::check`'s refusal now says "the server is busy" when the cause is this
  document's own limit. Give each limit its own message.
- **L4.** `forge-remote`: `projects` entries are compared to a canonicalized project path but
  are not canonicalized themselves, so a symlinked projects folder is refused. That is the safe
  direction; canonicalize both.
- **L5.** In the reopen-for-queued-joins path, a join whose `try_send` fails stays in `conns`
  but belongs to no actor, so it is never served or closed. This can't happen while
  `max_per_doc` ≤ `DOC_INBOX`; close it anyway.

## Checked and right

- N9: the build slot is freed exactly once (CAS 0→1 on the builder side, 0→2 on the actor's
  timeout or close; both sides covered, including actor close and quarantine).
- N3/N4: no `send`/`join` on an actor from the hub while serving; generation numbers stop a
  stale `Ended` from removing a newer actor.
- N2: per-name counters survive actor lifetimes, the server-wide cap is checked before
  spawning, and the abandoned thread decrements both on finish.
- N6: snapshot `seen` round-trips through FileLogStore (the test asserts it).
- forge-remote: `projects` required; `Path::starts_with` is per component, not a string prefix,
  and the project path is canonicalized.
- build.rs: the kernel id comes from git tree hashes plus a dirty flag; watching the
  directories only triggers reruns.

## Tests to add

1. Reconnect during close (H1): one client, drop the connection, reconnect immediately with a
   pending op; the op must be committed.
2. Close with a full inbox (H2): a test hook that fills the actor's inbox before the last Leave;
   a later join must be served.
3. Resync twice within the gap (M2): both answered (the second after the gap).
4. A hash build past BUILD_BUDGET (N9): `builds` returns to 0 exactly once, and a late Built is
   ignored.
5. Reopen after close (M1): the ops before the close are still readable.
